## 읽고 선택하는 순서

P01에서 ‘정원은 왜 건축과 별개여야 하는가’를 묻고, P02에서 선례와 적용 경계를 비교하며, P03에서 두 시간의 변화·설계 범위·돌봄·권한을 선택합니다. 개념 명칭과 방향은 작업 후보입니다.

R01은 606의 설치와 장기 사용, R02는 추가 후보 5개, R03은 물리적 접점과 수명·SWOT·다음 선택을 다룹니다. 606을 정원의 완성 사양으로 정하지 않았으며 후보들은 보류·혼합·대체할 수 있습니다.

00~01은 기존 집 적용의 경험과 조사 질문, 02~08은 국가 환경·수요·기존 제품, 09~12는 생활 마찰·차별화·SWOT, 13~15는 가구 후보와 실험입니다. 레일·모듈 A~D는 상위 공간 개념의 한 적용 갈래입니다. 16에서 기존 집 적용의 선택·보류 이유를 기록하고, 17에서 근거 경계를 확인합니다.

추천하는 다음 작은 행동은 어머니의 정원에서 물주기 후 정리 또는 바닥 청소 한 장면을 관찰하는 것입니다. 현재 화분 배치, 일반 선반·바퀴 받침, 수동 모듈 모형을 같은 조건에서 비교할 수 있습니다. 순서와 방향은 제안이며 사용자가 바꿀 수 있습니다.

## 수정과 보관

FigJam에서 직접 편집하는 데 플러그인 설치는 필요하지 않습니다. 플러그인은 JSON으로 새 보드를 만들거나 기존 연구 보드의 수정 문장을 별도로 보관할 때 선택적으로 사용합니다. 가져오기는 기존 내용을 덮어쓰지 않고 새 복사본을 만듭니다. 온라인 보드·JSON·보고서는 자동 동기화되지 않습니다.

텍스트를 편집한 뒤 길이가 늘면 카드와 섹션 높이를 조정합니다. JSON 내보내기는 문장·제목·상태·출처·섹션 색을 보관하고, 자유 배치·글꼴 등 모든 캔버스 스타일을 보관하지는 않습니다. FigJam 파일도 함께 보관합니다.

## 확인한 것과 남은 것

온라인 보드의 v0.3 전체 배치와 새 레퍼런스 세 영역을 시각적으로 확인했습니다. 24개 섹션·108개 카드·79개 출처 링크를 다시 읽어 원본 JSON과 일치함을 확인했고, 글꼴 누락과 섹션 밖 콘텐츠는 없었습니다. 기존 프롤로그·기존 집 선택 영역의 내용과 노드 ID도 유지했습니다.

DOCX는 LibreOffice로 실제 25쪽으로 변환해 모든 페이지의 글꼴·표·페이지 나눔을 시각적으로 확인했습니다. Microsoft Word에서 직접 열어 확인한 결과는 아닙니다. 본문·표·출처 링크·선택 기록은 편집 가능한 요소입니다.

로컬 플러그인은 구문, 전체 데이터 형식, 수정본 내보내기 모의 검사를 통과했습니다. 실제 사용자 환경에서 개발 플러그인을 설치·실행하거나 다운로드하는 과정은 확인하지 않았습니다. 계정의 플러그인 라이브러리나 커뮤니티에 게시하지 않았습니다.

조사는 공개 자료 기반입니다. 관찰·구매 수요 실험·식물 생장 시험·하중/누수/구동 안전·법규/인증·특허 신규성은 검증하지 않았습니다. 특정 해법을 완성 사양으로 확정하지 않았습니다.
